## 3. Business Objective

Enable the **Facility PAF Practitioner Search** to leverage the existing **Add New Practitioner** search workflow used by other PAF types.

The Facility PAF search must:

- Enforce NPI as the primary search criterion.
- Require a valid 10-digit NPI for standard searches.
- Support the controlled exception workflow when NPI is unavailable.
- Require minimum alternate search criteria for exception searches.
- Audit log exception searches.
- Reuse existing search criteria and validation behavior.
- Preserve existing business rules.

### Important architectural statement from the ticket

> No new NPI search logic is being introduced.

The Facility PAF workflow should reuse the existing **Add New Practitioner** search criteria and validation framework.

## 4. Business Need

To ensure consistency across all PAF types, the Facility PAF Practitioner Search must use the same **Add New Practitioner** search workflow currently implemented elsewhere in HCP.

The existing workflow enforces:

- NPI as the required primary search criterion.
- Validation of a valid 10-digit NPI.
- Controlled exception workflow when an NPI is unavailable.
- Minimum required search criteria for exception searches.
- Audit logging of exception search activity.

The Facility PAF implementation should align with the existing behavior without introducing new business rules.

## 5. Requirements

### 5.1 Practitioner Search — NPI Required Workflow

The standard practitioner search must use NPI as the primary and required search criterion.

Requirements:

- NPI is the primary search criterion.
- User must enter a valid 10-digit NPI before executing a standard practitioner search.
- Invalid NPI input must prevent the search from executing.
- Users without an NPI may use the approved exception workflow.
- Exception searches must use the approved minimum alternate criteria.
- Exception searches must be audit logged.

## 7. Acceptance Criteria

### AC1 — Facility PAF uses standard Add New Practitioner search workflow

**Given** a user is adding a practitioner through a Facility PAF.

**When** the Add New Practitioner search screen is displayed.

**Then** the system shall use the same search criteria, validation rules, and workflow behavior as other PAF types.

### AC2 — NPI is required for standard practitioner search

**Given** a user is performing a standard practitioner search.

**When** an NPI is not entered.

**Then** the search shall not execute. The user shall be prompted to provide a valid NPI, or use the approved exception workflow.

### AC3 — NPI validation is enforced

**Given** a user enters an NPI.

**When** the NPI is not exactly 10 numeric digits.

**Then** the system shall display a validation error and prevent the search from executing.

### AC4 — Valid NPI search executes successfully

**Given** a user enters a valid 10-digit NPI.

**When** the user initiates the search.

**Then** the system shall execute the practitioner search and return matching practitioner results.

### AC5 — Exception workflow is available when NPI is unavailable

**Given** a user does not have an NPI available.

**When** the user selects the approved exception workflow.

**Then** the system shall allow the user to perform an alternate practitioner search using the approved minimum search criteria.

### AC6 — Minimum criteria are required for exception searches

**Given** a user initiates an exception search.

**When** the required minimum exception criteria are not provided.

**Then** the system shall prevent the search from executing and display an appropriate validation message.

### AC7 — Exception searches are audit logged

**Given** a user performs an exception search.

**When** the search is submitted.

**Then** the system shall create an audit log record according to existing audit logging standards.

### AC8 — Consistent user experience across PAF types

**Given** a user performs practitioner searches in different PAF types.

**When** the workflows and validations are compared.

**Then** the behavior shall be consistent with the existing Add New Practitioner implementation.
