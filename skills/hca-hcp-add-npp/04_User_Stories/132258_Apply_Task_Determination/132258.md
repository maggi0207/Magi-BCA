## User Story

> As an MSP user, I want the system to use existing PAF task determination rules so that facility additions follow established workflows.

## Description

When the **"ADD NPP to Facility"** action is selected, the system will execute the same task determination logic currently used for:

- New practitioners
- Existing practitioners

The intent is to **reuse the existing PAF task determination engine** rather than creating a separate NPP-specific task determination mechanism.

## Acceptance Criteria

### Scenario 1: Net New Practitioner Task Generation

**Given** a Net New Practitioner is selected

**When** the user submits the **"ADD NPP to Facility"** action

**Then** the system creates tasks using the existing **New Practitioner PAF determination rules**.

### Scenario 2: Existing Inactive Practitioner Task Generation

**Given** an Existing Inactive Practitioner is selected

**When** the user submits the **"ADD NPP to Facility"** action

**Then** the system creates tasks using the existing **Existing Practitioner PAF determination rules**.

### Scenario 3: Rule Processing Success

**Given** valid practitioner data exists

**When** task determination executes

**Then** all applicable workflow tasks are generated successfully.

## Exception Handling

If task determination fails:

- Display an error.
- Prevent submission.
- Log workflow processing failures.
- Prevent creation of partial task sets.

This is ticket AC, even though it is not a numbered Given/When/Then scenario.

## Tasks

- Reuse existing task determination engine.
- Map the new action type to existing workflows.
- Validate task creation.
- Perform regression testing.
