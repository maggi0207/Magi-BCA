
Use this endpoint to load EmployerDetails records into the existing UI.

```text
POST /Employer/EmployerDetails/InsertEmployerDetails
```

Integrate with the existing Insert form.

The Insert operation is already working. Preserve its current functionality and avoid unnecessary changes.

## 5. Use the Correct API Payloads

Do not send unnecessary fields or placeholder values.

Inspect the actual backend request DTOs and Swagger definitions before implementing the frontend payloads.

For Update:

- Include employerId.
- Include only the fields required by the existing Update contract.
- Do not send `"string"`, default dates, or unrelated fields.

For Delete:

- Include only the required employer identifier and any mandatory context fields.
- Do not send the entire EmployerDetails object unless the backend contract requires it.

Use the existing request and response models wherever available.

Do not invent new API contracts.
