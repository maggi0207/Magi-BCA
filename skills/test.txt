User Story: Restrict NPP PAF Submission Access to MSP User Role
Title:
Configure Role-Based Access Control for NPP PAF Submission – MSP Users Only

Description:
As a system administrator, I need to restrict the ability to submit an ADD NPP PAF request so that only users assigned to the MSP role can create and submit Non-Defined Practitioner (NPP) PAFs, ensuring compliance with business rules and preventing unauthorized submissions.

Business Value:
Ensures NPP onboarding requests are initiated only by authorized MSP users, improving governance, reducing processing errors, and maintaining compliance with credentialing workflows.

Requirements
Only users assigned to the MSP role may create and submit an ADD NPP PAF.

Non-MSP users must not be able to access, initiate, submit, or complete the ADD NPP PAF process.

Access restrictions must be enforced at both the UI and service/API layers.

Appropriate messaging must be displayed when unauthorized users attempt to access the functionality.

Security configuration must be consistent across DEV, QA, and PROD environments.

Acceptance Criteria
AC1 – MSP Users Can Submit ADD NPP PAF
Given a user is assigned the MSP role
When the user accesses the NPP functionality
Then the user can create and submit an ADD NPP PAF request.

AC2 – Non-MSP Users Cannot Submit ADD NPP PAF
Given a user is not assigned the MSP role
When the user attempts to access or submit an ADD NPP PAF
Then access is denied and the request cannot be submitted.

AC3 – UI Security Enforcement
Given a non-MSP user is logged in
When the user navigates to the NPP workflow
Then the ADD NPP PAF option is hidden or disabled based on application standards.

AC4 – Backend Security Enforcement
Given a non-MSP user attempts to bypass the UI and directly invoke the submission service
When the request is processed
Then the system rejects the request and returns an authorization error.

AC5 – Consistent Security Configuration
Given role-based security has been configured
When validation is performed in DEV, QA, and PROD
Then only MSP users have permission to submit ADD NPP PAF requests in all environments.

AC6 – Auditability
Given an ADD NPP PAF submission is made
When the request is successfully submitted
Then the system records the submitting user and timestamp for audit purposes.

Technical Tasks
Identify the ADD NPP PAF workflow entry point(s).

Update role-based security configuration to allow MSP role access only.

Implement UI-level access restrictions.

Implement API/service-level authorization validation.

Configure and validate security in DEV.

Promote and validate security in QA.

Promote and validate security in PROD.

Perform positive and negative access testing.

Update security and workflow documentation.

Exception Handling
If a user's role cannot be determined, deny access by default.

If the authorization service is unavailable, deny submission and log the error.

If a non-MSP user attempts direct API submission, reject the request and return an authorization error.

Any security configuration discrepancies between environments must be resolved before deployment approval.
