**Root Cause**
IdpClient.UserAccountExistsAsync dereferences email before making the request:

```csharp
Uri.EscapeDataString(email.Trim())
```

NPP Add New permits omitted email and maps it using `_model.Email?.Trim()`. The shared ConfirmationWizardModal.SaveNewPractitionerAsync called IdP for every non-recruitment practitioner, including those with null email.

Classic Begin PAF and Begin NPP PAF use this same modal.

**Fix**
Added a single guard at the wizard call site:

```diff
-if (!practitioner.IsRecruitmentPractitioner)
+if (!practitioner.IsRecruitmentPractitioner &&
+    !string.IsNullOrWhiteSpace(practitioner.EmailAddress))
 {
     accountExists = await Idp.UserAccountExistsAsync(practitioner.EmailAddress);
 }
```

Null, empty, or whitespace email skips the account lookup. Supplied email still receives the existing IdP check, including rejection when already in use. Duplicate-practitioner checks and recruitment behavior remain unchanged.

**Validation**
Client Release build **passed**, including a final rebuild after formatting correction. No editor errors were found. No direct wizard/IdP unit-test harness was located, so UI behavior remains for manual QA verification.
