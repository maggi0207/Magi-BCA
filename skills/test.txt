# Project Architecture & Codebase Deep Analysis – Facts Consultation MVC Application

## Objective

Perform a comprehensive, evidence-based analysis of the existing Facts Consultation application. Understand the complete application architecture, business functionality, technical implementation, data flow, and dependencies.

The goal is to document the project in a way that allows any developer, architect, or new team member to understand how the application works without requiring extensive guidance from the original developers.

- Explain the purpose of each major folder and project.
- Identify the MVC implementation and how responsibilities are separated.
- Highlight any legacy components, unused files, duplicate implementations, or tightly coupled modules.

## 3. MVC Architecture – Detailed Analysis

Explain:

- **Model:** Business entities, data models, validation rules, and data transformations.

## Analysis Rules

1. Read the actual source code before making conclusions.
2. Do not assume the architecture based only on folder names.
3. Trace important functionality across multiple files.
4. Reference actual file paths, class names, method names, and relevant code sections.
5. Clearly distinguish implemented functionality from inferred behaviour.
6. Do not invent business rules, APIs, database tables, or architectural components.
7. Identify areas where the source code does not provide enough information.
8. Avoid generic documentation that could apply to any MVC application.
9. Explain technical concepts in clear language while maintaining technical accuracy.
10. Keep the documentation detailed, structured, and useful for onboarding, debugging, and future development.
