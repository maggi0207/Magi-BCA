2. **Practitioner-only method and route**
   - Method: `GetPractitionerFacilitiesAddedToAndActiveAtAsync(string practitionerKey)`
   - Route: `[HttpGet("PractitionerFacilitiesAddedToAndActiveAt/{practitionerKey}")]`
   - The new SQL selects active assignment facility keys and applies the existing facility eligibility filters, with no `AllUserFacilitiesCte`, `USERENTITY`, user ID, or fake user ID.

3. **Existing query unchanged:** `GetFacilitiesPractitionerAddedToAndActiveAtAsync(userId, practitionerKey)` and its user-scoped SQL were not edited. Existing `TaskDeterminationService` callers and routes remain untouched.

4. **Lock condition and message:** For NPP, Add Address is disabled and the message shown only when `_primaryAddresses.Any() && activeFacilities.Any()`. Exact message: “The practitioner currently holds privileges at one or more HCA facilities. The primary address cannot be changed.” An empty result or missing Primary leaves Add enabled. Non-NPP does not call the new method.

5. **Error path:** Missing practitioner key, null result, or request exception disables Add Address and shows the existing `NotificationService` error notification pattern. The check is performed before the task finishes initialization; after an error, reopening the task is needed to retry.

6. **Builds:** Cactus API, Shared, and Client builds all succeeded. `git diff --check` passed.

7. **Remaining gaps:** No automatic retry is provided after a failed check. No change was made to `ValidateAndSaveAddresses`, the existing user-scoped query/route, or other PAF flows.
