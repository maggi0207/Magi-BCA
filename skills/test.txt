2. **NPP signal**

The parent passes the selected task as requested:

```razor
IsNppPaf="@(StateContainer.PafState.TaskSelected == TaskType.Npp)"
```

3. **Hidden versus still loaded**

NPP hides Home, Credentialing, and Alternate sections with conditional CSS classes. Their component refs and address collections remain loaded so existing save behavior can still access them. Primary remains displayed, and Add Address remains enabled.

```razor
<SpaceItem Class="@(IsNppPaf ? "hide" : "")">
    <ManageAddresses ... Addresses="@_homeAddresses" />
</SpaceItem>
```

4. **Empty-state string**

Rendered beside the Primary section when the NPP Primary collection is empty:

```razor
@if (IsNppPaf && !_primaryAddresses.Any())
{
    <Text>No Primary Address on File</Text>
}
```

5. **Group UI skipped**

The Primary editor forwards `IsNppPaf` to the existing modal. For a new address, the modal selects its existing manual-entry path instead of the Practice Group question:

```csharp
if (IsNppPaf)
{
    IsEditingPracticeGroupAddress = "No";
}
else
{
    _viewState = PracticeAddressModalViewState.PracticeQuestion;
}
```

No group disclaimer was added.

6. **Unchanged behavior confirmation**

`ValidateAndSaveAddresses()` was not changed. No affiliation check, privileges API, Add Address disabling, Fax rule, `GetCredentialingTypeRtk`, CACTUS, or other PAF task flow was edited. Begin PAF remains unchanged.

7. **Build result**

Client project build succeeded:

```text

```

Final diagnostics report no errors in all six changed files.

8. **Remaining gaps**

The requested Primary-only display is implemented, but unchanged `ValidateAndSaveAddresses()` still requires confirmed Home and Credentialing addresses for completion. Since the instruction was not to change that method, a PAF without those confirmed address groups may still be offered Save for Later rather than complete.
