**A. Practitioner license queries**

A private practitioner-keyed list helper exists in `CrudPractitionerLicensesOperation.cs`:

> `private async Task<ICollection<Providerlicenses>> GetExistingLicensesAsync(string licenseTypeRtk)`

> `SELECT * FROM VisualCactus.PROVIDERLICENSES (NOLOCK) WHERE PROVIDER_K = @ProviderK AND LICENSE_RTK = @LicenseTypeRtk`

It uses the operation’s `PractitionerKey` and returns rows for the specified license RTK; it has no `ACTIVE` or `STATUS_RTK` filter.

The other helper, `LoadActiveLicenseRecordsAsync(string practitionerKey, string licenseRtk, string institutionK)`, filters `PROVIDER_K = @PractitionerKey`, `LICENSE_RTK = @LicenseRtk`, `ACTIVE = 1`, and `State IS NOT NULL`. Its SQL does not filter by `institutionK`. Neither helper is a public repository/API list method.

The closest public license search is `PractitionerExpiredLicenseQueryBuilder.GetCoreQuery(...)`. It filters by practitioner key, excludes listed license RTKs, and requires `PERSISTENTVERIFICATIONS = 1` and non-null expiration date; it is an expired/work-queue query, not an all-licenses list.

**B. State-license RTK**

`NPDBSTATEx` is present in `CrudPractitionerLicensesOperation.cs`, both in the state-license processing list and the `InsertLicenseAsync("NPDBSTATEx", ...)` call.

**C. Closest reuse**

The private `GetExistingLicensesAsync(string licenseTypeRtk)` helper can return all practitioner rows for the supplied license RTK without Active/Status filtering. It is not a Cactus API method, however. The API repository currently exposes search/work-queue operations rather than a list-by-practitioner operation, so a public list endpoint is not already available.

**E. CVI type and status columns**

 CactusUpdater.cs resolves the type with:

> `var credentialingTypeRtk = credentialingTypeRtkOverride ?? pafDataContext.Paf.GetCredentialingTypeRtk();`

It passes that value as both `GroupTypeRtk` and `CredentialingTypeRtk`. The group operation writes `CREDENTIALINGGROUP.TYPE_RTK`; `CrudEntityCredentialingOperation.cs` writes `CREDENTIALING.TYPE_RTK`.

The credentialing operation writes status separately:

> `parameters.Add("@CREDENTIALINGSTATUS_RTK", auditRecord.CredentialingstatusRtk = CredentialingStatusRtk ?? await ResolveCviStatusRtkAsync());`
