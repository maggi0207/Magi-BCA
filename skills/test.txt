**Status Chip Path**
The chip binding in `PafQueueSearchCriteria.razor` is:

> `Checked="_selectedStatusFilterOptions.Contains(status)" CheckedChanged="_checked => OnStatusCheckChange(status, _checked)"`

The handler sends the selected statuses through the existing criteria-change callback. The client search request writes:

> `Status = BuildStatusFilterForSearchCriteria(_searchCriteriaModel),`
>
> `TaskType = _searchCriteriaModel.TaskTypeFilter.Value.GetValueOrDefault(TaskType.Unknown),`

The API query applies each ordinary status as `paf.IndexedPafStatus = @PafStatus{idx}` and ORs the selected statuses. Separately, NPP adds `paf.IndexedTaskSelected = @TaskType`; these predicates are combined with AND. The issue was that clicking Submitted while Saved was selected added Submitted without removing Saved.

For NPP PAF, a status-chip click now replaces the previous status selection with the clicked status. Other task types retain their existing multi-select behavior. The NPP PAF label and search path are unchanged.
