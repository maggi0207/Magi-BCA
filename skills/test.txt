1. **Files changed:** `NppTaskForm.razor.cs` and `ModelExtensions.cs`.

2. **132529:** Selected facility state is already carried as `FacilityValue.State`. For each selected facility in CA, LA, NV, KY, or TX, the NPP Complete check compares that state with the state on the practitioner’s loaded licenses, case-insensitively:
   > `string.Equals(license.State?.Trim(), facilityState, StringComparison.OrdinalIgnoreCase)`

   A matching state on the entered new license also counts. If none matches, Complete is blocked with the requested message, for example: `A state license in the state of 'TX' is required for PAF submission.` Save for later remains available.

3. **132267:** `IsSubmittable()` now checks NPP only when `TaskSelected == TaskType.Npp`:
   > `if (pafData.TaskSelected == TaskType.Npp && (pafData.NppTask == null || IsTaskInError(pafData.NppTask))) return false;`

   `IsTaskInError` requires a required task to have `Status == TaskStatus.Complete`. Other PAF types are unaffected. This gates entry to Review & Submit; it does not make submission succeed.

4. **Unchanged:** `GetCredentialingTypeRtk`, submit flow, Cactus code, and PafFile/upload code were not edited.

5. **VA+PA Yes:** When VA/military is Yes and PA is Yes, `ShouldShowStateLicenses` hides state licenses, so the 132529 facility-state check is intentionally skipped.

6. **Build:** Client build succeeded. `git diff --check` and the separate whitespace check for the untracked NPP code-behind reported no issues.

7. **Remaining gaps:** No automated behavior test or live UI validation was run; verification was the Client build and whitespace checks.
