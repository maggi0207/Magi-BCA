132687 : NPP Reports

Title: Generate and Distribute Monthly Add NPP Activity Report

Objective
Provide an automated monthly report that summarizes Add NPP request activity for the prior month and distributes it to the required reporting groups on the 1st of each month.

Business Value
This feature gives the business consistent oversight of Add NPP request volume and CPC routing activity, reduces manual reporting effort, and improves operational tracking.

Scope
The report shall:

Run automatically on the 1st of each month.
Use the previous calendar month as the reporting period.
Include:
Total number of Add NPP requests received.
Total number of Add NPP requests routed to CPC.
Percentage of received Add NPP requests routed to CPC.
Distribute the report to:
PARA.DL American SSC CPC FO MGMT
PARA Credential Reporting
Business Rules
The report is generated monthly.
The reporting period is the prior calendar month.
If no requests were received, the report still generates and shows zero values.
Percentage routed to CPC must not fail on divide-by-zero; display 0% when no requests were received.
Report distribution is automated.

132688 : NPP: Reports Monthly Add NPP Request Activity Report
User Story: Monthly Add NPP Request Activity Report
Title
Generate and Distribute Monthly Add NPP Request Activity Report

User Story
As a Credentialing Operations Leader

I want a monthly report generated and automatically distributed

So that leadership and reporting teams can monitor Add NPP request volume, CPC routing activity, and operational performance.

Business Requirement
The system shall generate a monthly Add NPP Activity Report summarizing activity for the previous calendar month.

The report shall be automatically generated and distributed on the 1st day of each month.

The report is intended to provide oversight and operational tracking of Add NPP request processing and routing activities.

Report Schedule
Requirement	Value
Frequency	Monthly
Run Date	1st day of each month
Reporting Period	Previous calendar month
Distribution Method	Automated Email Distribution
Example
Run Date: August 1

Reporting Period: July 1 – July 31

Report Metrics
The report shall include the following metrics for the reporting period:

Metric 1
Total Number of Add NPP Requests Received

Definition:

Count of all Add NPP requests received during the reporting period.

Metric 2
Total Number of Add NPP Requests Routed to CPC

Definition:

Count of all Add NPP requests routed to CPC during the reporting period.

Metric 3
Percentage Routed to CPC

Calculation:

Percentage Routed to CPC =
(Total Routed to CPC ÷ Total Requests Received) × 100

Display as percentage rounded to two decimal places.

Example:

Received = 100

Routed to CPC = 35

Percentage = 35.00%

Distribution Requirements
The completed report shall be automatically distributed to the following distribution groups:

Distribution List 1
PARA.DL American SSC CPC FO MGMT

Distribution List 2
PARA Credential Reporting

Acceptance Criteria
Scenario 1 – Monthly Report Generation
Given Add NPP request activity exists during the reporting period

When the scheduled report executes on the 1st of the month

Then a report is generated containing all required metrics.

Scenario 2 – Previous Month Reporting
Given the report runs on the 1st day of a month

When the report is generated

Then only activity from the previous calendar month is included.

Scenario 3 – CPC Routing Count
Given requests were routed to CPC during the reporting period

When the report is generated

Then the total routed count is displayed.

Scenario 4 – CPC Routing Percentage Calculation
Given requests were received and routed

When the report is generated

Then the percentage routed to CPC is correctly calculated.

Scenario 5 – Automated Distribution
Given the report is generated successfully

When report processing completes

Then the report is emailed to:

PARA.DL American SSC CPC FO MGMT

PARA Credential Reporting

Scenario 6 – No Activity During Reporting Period
Given no Add NPP requests were received during the reporting period

When the report is generated

Then the report displays:

Total Requests Received = 0

Total Routed to CPC = 0

Percentage Routed to CPC = 0%

And the report is still distributed.

Exception Handling
Report Generation Failure
Failure details shall be logged.

Notification shall be sent to the support team or reporting administrator.

Email Distribution Failure
Distribution errors shall be logged.

Failed recipient groups shall be identified in the log.

Data Extraction Failure
Report generation shall terminate gracefully.

Error details shall be captured for support review.

Divide-by-Zero Handling
If Total Requests Received = 0

Percentage Routed to CPC shall display as 0%

No calculation errors shall occur.
