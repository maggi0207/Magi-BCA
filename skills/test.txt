The source points to a specific submit-only omission: the existing-practitioner NPP eligibility query passes `TaskListParameters.UserId` to `FacilityClient`, but `CactusReloadHelper` never sets it; the UI TaskController does. That makes the interpolated route’s `{userId}` segment empty. The Cactus action itself has no “practitioner not found” 404 branch, though I don’t have the runtime Cactus log to confirm the exact requested URL.

**A. FacilityClient URL**

`FacilityClient.cs`:

> `$"{ApiBasePath}/{userId}/PractitionerNotAddedToOrInactiveAt/{HttpUtility.UrlEncode(practitionerKey.Trim())}"`

`ApiBasePath` is `"api/Facility"`. Arguments are `userId` and `practitionerKey`.

**B. Matching Cactus action**

`FacilityController.cs`:

> `[HttpGet("{userId}/PractitionerNotAddedToOrInactiveAt/{practitionerKey}")]`

The action logs “Getting facilities from Cactus for userId … where practitioner … is not added or is inactive at” and returns `Ok(await _facilityRepository.GetFacilitiesPractitionerNotAddedToOrInactiveAtAsync(userId, practitionerKey))`. There is no practitioner-not-found 404 branch; the repository method runs a query and returns its results. I do not have the Cactus runtime log to confirm the actual URL received.

**C. When the service calls this method**

`TaskDeterminationService.cs`: in **ExistingPractitioner** mode, when `IsMspUserMode` is true, NPP eligibility calls:

> `GetUserFacilitiesNotAddedToOrInactiveAtAsync(listParameters.UserId, practitioner.Key)`

The NewPractitioner branch adds NPP directly for MSP and does not make this facility query. So the reported stack indicates the submit reload entered ExistingPractitioner mode.

**D. Submit-time arguments**

`CactusReloadHelper.cs` sets `PractitionerId = _formData.Practitioner.Id` and `IsMspUserMode = _user.IsMspUser()`, but does **not** set `UserId`. The service fetches that practitioner and passes `practitioner.Key` as the practitioner key. `UserId` therefore remains its default `null`.

By contrast, `TaskController.cs` sets `listParameters.UserId = currentUser.GetUserId()` from the authenticated `HttpContext.User`.

**E. Why task selection can work while submit fails**

The UI’s task-selection request goes through `TaskController`, which populates both MSP mode and user ID before calling the same task-determination service. Submit calls that service directly through `CactusReloadHelper`; it populates MSP mode but omits user ID. With a null user ID, the FacilityClient interpolation produces an empty `{userId}` route segment, likely resulting in route mismatch/404. The supplied stack does not include the actual request URL, so that final routing detail is inferred from the code.

**F. Existing 404 handling**

No 404-to-empty-list or skip pattern was found for this call. The Cactus action returns `Ok(repositoryResult)` and the repository query can return an empty collection; it does not return 404 when a practitioner has no matching facilities. `BaseApiClient.TryApiCall` explicitly rethrows `HttpRequestException` for `NotFound`.
