**A. Completed Queue Host**

There is no separate CPC-only Completed Queue component. The CPC dashboard hosts the shared PAF queue, whose criteria component switches between Open and Completed:

- `CpcDashboardPage.razor` and `CpcDashboardPage.razor.cs`
- `SharedPafQueue.razor` and `SharedPafQueue.razor.cs`
- `PafQueueSearch.razor` and `PafQueueSearch.razor.cs`
- `PafQueueSearchCriteria.razor` and `PafQueueSearchCriteria.razor.cs`

**B. Type Dropdown and Source**

The existing dropdown is in `PafQueueSearchCriteria.razor`:

> `DataSource="@_taskTypeFilterOptions"`  
> `@bind-Value="_selectedTaskTypeValue"`  
> `ValueName="@nameof(FieldOption<PafType?>.Value)"`  
> `LabelName="@nameof(FieldOption<PafType?>.Text)"`

Its options are built by the static `_taskTypeFilterOptions` list in `PafQueueSearchCriteria.razor.cs`. This is a **static in-repo list**, not reference data from an API or database. The selected value is stored in the existing criteria model.

**D. NPP Label Present?**

**No.** Neither “Add NPP to Facility” nor “ADD NPP to Facility” is in the current dropdown options. `TaskType.Npp` already exists, but its enum description is “NPP PAF”; the list has no `Npp` option.

**E. Query Filter**

The selected dropdown value is passed as `PafSearchParameters.TaskType` in `PafQueueSearch.razor.cs`:

> `TaskType = _searchCriteriaModel.TaskTypeFilter.Value.GetValueOrDefault(TaskType.Unknown)`

The request also passes `QueueMode = Mode.GetDescription()` and the selected `Status` values. In `PafSearchQueryBuilder.cs`, the type predicate is:

> `where.Part += "paf.IndexedTaskSelected = @TaskType AND ";`

`TaskType.Unknown` leaves that predicate off; the special `CalculatedUnlocked` option filters by `IndexedLockedBy IS NULL`. Completed membership is based on the selected status values, with `QueueMode` also used by special calculated-failure status handling.

**F. Completed Status**

 PafStatus.cs defines `AcceptedByCpc` with description “Completed” and comment `// aka Completed Queue`. CPC Completed status options also include `ProcessedManually`, `RejectedToMsp`, `Deleted`, `CalculatedMyFailedPafs`, `SubmittedByRecruiter`, and `RecruitmentR0999`. The repository filters ordinary statuses through `paf.IndexedPafStatus = @PafStatusN`; calculated statuses use their corresponding predicates in `PafStatusFilter.cs`.

**G. NPP Type Persistence**

`PractitionerActionFormData.cs` has both:

> `public PafType Type { get; set; }`  
> `public TaskType TaskSelected { get; set; } = TaskType.Unknown;`

`PafType` distinguishes only `ManageNewPractitioner` and `ManageExistingPractitioner` in `PafType.cs`; it does not identify NPP. NPP is `TaskType.Npp` (`14`). `PractitionerActionForm.cs` indexes it with:

> `IndexedPafType = _formData.Type;`  
> `IndexedTaskSelected = _formData.TaskSelected;`

**Filterable as-is: Yes**, through `TaskSelected` / `IndexedTaskSelected`. No new PAF type field or API is indicated by the existing data path.
