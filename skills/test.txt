**B. Issues Found**

- **P2, fixed:** The NPP state-license helper processed state-license input even when the NPP form hides those fields. It now checks `NppTask.ShouldShowStateLicenses(nppTask)` and returns when false. This also prevents an irrelevant missing-selection warning from replacing the sanction warning.

Net-new NPP could therefore run Add-Practitioner’s default license checklist. The new-provider call now passes false only for NPP.
- **P2, residual call-order risk:** In `UpdateFromNewAsync`, `CreateStandardCviRecordsAsync` still runs before the later generic license call. Existing NPP processes licenses before specialty/CVI, but net-new NPP’s shared path creates CVI/EA first. I left this unchanged because it predates this review and changing the shared ordering has broader transaction implications; verify the intended ordering before commit.

Other reviewed gates are consistent with the stated rules: existing NPP provider updates return the practitioner key without updating demographics; active matching licenses are not updated; the Primary address guard checks any active, non-ended Primary association; existing NPP specialties use create-if-missing rather than full reconciliation; historical inactive EAs with both dates return before update; sanction image failures are logged and do not prevent the state-license helper from running.
