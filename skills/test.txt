## 2. /Npp No-NPI click today (quote)

The page uses:

```razor
<PractitionerSearchForm ... ForceNpiSearchMode="@_isNppEntry"/>
```

`_isNppEntry` is:

```csharp
private bool _isNppEntry => NavigationManager.ToBaseRelativePath(NavigationManager.Uri)
    .Equals(PageUri.PractitionerNppSearchUri.TrimStart('/'), StringComparison.OrdinalIgnoreCase);
```

The link is rendered by `PractitionerSearchForm.razor`:

```razor
<a href="javascript:void(0)" @onclick="SwitchToExceptionSearch">
    No NPI available? Search without NPI
</a>
```

The handler is:

```csharp
private async void SwitchToExceptionSearch()
{
    _currentSearchMode = SearchMode.ExceptionSearch;
    _model.PractitionerNpi = string.Empty;
    _showNpiValidationError = false;
    _npiValidationMessage = string.Empty;
    await OnResetCallback.InvokeAsync();
    StateHasChanged();
}
```

`/Practitioner/Search/Npp` starts in NPI mode because `ForceNpiSearchMode` prevents the non-flexible user from switching to exception mode during initialization. The link is still rendered in NPI mode, so NPP can click it today.

Begin PAF MSP defaults to exception mode:

```csharp
if (!_isRecruitmentUser && !_isPsgUser && !ForceNpiSearchMode)
{
    SwitchToExceptionSearch();
}
```

Recruitment/PSG users start in NPI mode and can use the link. `SwitchToNpiSearch()` clears exception values for flexible users; MSP uses:

```csharp
await JsRuntime.InvokeVoidAsync("history.back");
```

**D. Validation today**

`IsExceptionButtonEnabled()` for flexible users requires Reason, Last Name, and one additional criterion:

```csharp
return !string.IsNullOrWhiteSpace(_selectedReason)
    && !string.IsNullOrWhiteSpace(_model.PractitionerLastName)
    && hasAtLeastOneAdditionalCriterion;
```

The additional criterion is First Name, DOB, SSN, or Email.

Existing messages:

```csharp
"Must be a minimum of 2 alpha characters"
"Must be a minimum of 1 alpha characters"
"Please enter at least one additional search criteria along with Last Name."
```

Gaps against 131787:

- Exact required Reason behavior is only present for flexible users.
- Last Name is minimum 2 characters, but the message does not match the ticket wording and does not explicitly enforce alpha-only characters.
- First Name is effectively optional for flexible users, but no meaningful 1-alpha validation exists because the current condition checks `Length < 1`.
- No License validation exists.
- No State/License pair validation exists.
- Last-name-only is disabled for flexible users because an additional criterion is required.
- MSP exception validation follows older mutual-exclusivity rules and is not NPP-specific.

```csharp

    "At least one additional search criteria is required along with Last Name");
```

There are not two current APIs. Both NPI and exception search use the same endpoint, with different `SearchType` values and query builders.
