**A. Call Chain**

For a completed existing-practitioner NPP, `CactusUpdater` calls `CreateStandardCviRecordsAsync`. That shared method iterates `Paf.SelectedFacilities` and calls `CrudEntityAssignmentOperation` for each facility. Net-new processing also reaches the shared CVI/assignment path. No NPP-specific EA operation was found; the shared operation determines whether to insert or update.

**B. Create + Facility**

The facility source is `Paf.SelectedFacilities`; the updater passes `facility.FacilityKey` as `EntityKey`. The operation looks for an existing assignment by provider, entity, and record type:

> `ea.PROVIDER_K = @ProviderK`  
> `AND ea.ENTITY_K = @EntityKey`  
> `AND ea.RECORDTYPE = 'E'`

> `if (existingRecord == null) return await InsertPractitionerEntityAssignmentsAsync();`

A match follows the update path. I found no explicit “facility not found” log-and-stop handling; a missing facility lookup can lead to a null dereference when resolving the entity key during insert.

**C. Security `RECFLT_INT`**

The value appears as a literal, not a named constant. `ResolveWebPubishStatus()` returns `"RECFLT_INT"` only when `TaskSelected == Recruitment`; otherwise it returns `CommonCactusRtks.NoneRtk`. NPP therefore does **not** get the requested Internal Use Only setting on insert.

**E. Historical Preserve**

The lookup does not filter out inactive assignments or assignments with start/end dates. For an inactive match, the general branch sets `Active = true`, assigns a resolved status, and updates status/category dates and `Dateentered`. There is no guard to preserve an inactive assignment with historical dates. The present-date fields are not explicitly rewritten in that branch, but the record is still modified.
