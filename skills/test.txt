**Why Duplicated**
Both entries use the same action catalog. NPP availability depends on MSP role and practitioner/facility eligibility, **not the button clicked**. The dedicated entry’s search flags stop before `/Paf/New` action selection. This explains the observed classic Begin PAF behavior.

This preserves the dedicated NPI-first workflow.

- **Eligibility gate:** adjust only the NPP additions in `TaskDeterminationService`. Eligibility alone cannot distinguish the two entry paths today; it would need propagated entry intent to enforce exclusivity.

Simply hiding ADD NPP within the dedicated NPP path would leave that button unable to start an NPP request, so I do not recommend that approach.
