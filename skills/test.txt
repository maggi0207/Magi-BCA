# Fix FACTS Framework ContextHeader – Employer API 500 Error

## Problem

When executing Employer API endpoints through Swagger at:

`http://localhost:8007/swagger/index.html?urls.primaryName=Employer`

The API returns HTTP 500.

Error:

```text
System.ArgumentException:
Requested value 'employer' was not found.
```

Stack trace indicates the failure occurs in:

```text
FACTS.Framework.Service.Middleware.ContextHeader.GetContext(...)
FACTS.Framework.Service.Middleware.ContextHeader.InvokeAsync(...)
```

The exception is related to enum parsing:

```text
System.Enum.Parse(...)
Requested value 'employer' was not found.
```

## Objective

Investigate and fix the FACTS framework request-context configuration issue without modifying unrelated Employer CRUD functionality.

## Investigation Steps

1. Inspect the Employer service startup and middleware configuration.
2. Identify how `ContextHeader` is registered and invoked.
3. Find the request header or configuration value containing `employer`.
4. Locate the `TStorage` enum or equivalent framework enum used by `ContextHeader`.
5. Identify the valid enum values from the actual source code or framework metadata.
6. Compare the current Employer API request headers with those used by working services.
7. Inspect Swagger configuration and any custom header configuration.
8. Check whether the Employer service is using an incorrect storage/context value.
9. Determine whether the issue is caused by:
   - Incorrect request header
   - Incorrect service configuration
   - Invalid enum value
   - Framework version mismatch
   - Middleware registration or initialization

## Fix Requirements

- Follow the existing FACTS framework configuration pattern.
- Compare with a working service such as Customer, Claims, or another relevant service.
- Use the actual supported `TStorage` enum value.
- Do not guess enum values.
- Do not remove ContextHeader middleware as a workaround.
- Do not disable authentication, authorization, or request-context validation.
- Do not modify Employer BusinessLogic or database operations unless the investigation proves they are involved.
- Preserve existing API contracts and CRUD functionality.

## Validation

After applying the fix:

1. Restart the Employer service.
2. Open Swagger.
3. Execute `GetEmployerDetails`.
4. Execute `InsertEmployerDetails`.
5. Execute `UpdateEmployerDetails`.
6. Execute `DeleteEmployerDetails`.
7. Confirm that the ContextHeader exception no longer occurs.
8. Confirm that the requests reach the appropriate controller and BusinessLogic.
9. Verify that database operations work correctly.
